# Production Closure Gates

This checklist separates repository evidence from approvals and live evidence
that cannot be truthfully generated by source code. A release is not approved
until every applicable gate is recorded by its named owner.

## 1. Repository gate — complete

Evidence recorded on 2026-10-12:

- `uv run --extra dev pytest -q` — **301 passed, 3 skipped**.
- `git diff --check` — no whitespace errors.
- Health and readiness probes execute a SQLAlchemy 2-compatible `SELECT 1`.
- Production startup rejects an unsafe JWT secret, wildcard CORS, missing
  `DATABASE_URL`, and `DEBUG=true`.

The skipped tests are integration scenarios that require optional external
providers; they must be exercised during the pilot gate below.

## 2. Credential and deployment gate — owner: platform operator

- [ ] Set a unique `JWT_SECRET_KEY` (at least 32 characters) in the production
  secret manager; do not use any value in `.env.example`.
- [ ] Configure a production `DATABASE_URL` and run the migration/init process.
- [ ] Set explicit HTTPS `CORS_ORIGINS`; wildcard origins are prohibited.
- [ ] Configure required LLM/provider credentials and confirm least-privilege
  scopes.
- [ ] Configure Stripe, webhook, error-tracking, and object-storage credentials
  only if those features are enabled.
- [ ] For SSO, validate provider metadata and complete an authenticated
  SAML/OIDC/LDAP login round trip; configuration helpers intentionally remain
  `pending_provider_validation` until this evidence exists.
- [ ] Record the secret-manager version identifiers, rotation owner, and next
  rotation date in the deployment change record. Never record secret values.

Acceptance evidence: a deployment startup log showing successful validation,
and a secret-manager/change-ticket reference reviewed by the platform operator.

## 3. Security and compliance gate — owner: security approver

- [ ] Review RBAC roles and API-key scopes for the pilot tenant.
- [ ] Confirm mutation audit events are reaching the retained audit sink.
- [ ] Review data retention, incident response, and privacy/export obligations.
- [ ] Run the applicable OWASP/LLM security scan and triage findings.
- [ ] Approve the threat model and residual-risk statement.

Acceptance evidence: dated approval, findings disposition, and a link to the
audit retention configuration.

## 4. Operational readiness gate — owner: service owner

- [ ] Deploy a staging environment using production-like backing services.
- [ ] Verify `/live`, `/ready`, and `/health`; confirm unhealthy dependencies
  return non-success readiness.
- [ ] Exercise backup and restore for the database and blueprint artifacts.
- [ ] Test rollback to the previous deployment and document the rollback time.
- [ ] Configure alert routing, on-call owner, rate limits, and error tracking.

Acceptance evidence: timestamped deployment record, health-probe output,
backup/restore evidence, and a successful rollback drill.

## 5. Pilot gate — owner: product owner and pilot sponsor

- [ ] Identify pilot tenant, permitted workflows, data classification, and
  explicit user consent.
- [ ] Run the skipped external-provider integration scenarios with pilot
  credentials in an isolated environment.
- [ ] Execute at least one agent run, workflow run, retry, cancellation, and
  blueprint installation end-to-end.
- [ ] Review audit trail, telemetry, cost records, failure handling, and user
  feedback.
- [ ] Define measurable success criteria before launch (availability, error
  rate, latency, task completion, cost ceiling, and satisfaction target).
- [ ] Obtain pilot-sponsor go/no-go sign-off.

Acceptance evidence: pilot report containing only anonymized identifiers,
metrics against targets, outstanding risks, and the sponsor decision.

## 6. Release decision

Release requires signed completion of Gates 2–5. A failed gate means hold or
roll back; it must not be reclassified as complete merely because local tests
pass. Attach the completed evidence to the release/change record and link it
from the deployment ticket. Use [RELEASE_EVIDENCE_RECORD.md](RELEASE_EVIDENCE_RECORD.md)
as the standard evidence template.
